# HFSS数值策略与完成通知

## 最新单例设置

- 可见Ansys Electronics Desktop 2024 R2，HFSS；由本地AEDT接口控制。
- 14核、1任务、1组，串行；核数须用真实启动证据确认，不能只看Python已启动。
- Setup19宽带自适应0.1–15GHz，MaxDeltaS=0.005；分阶段网格控制。
- 目标10–11万单元；已获准将≤11.2万记作轻微超限。最新单例103787、22轮自适应。
- Sweep1插值0.01–15GHz、0.01GHz导出间隔，1%插值容差；不强制passivity。
- 端口每口2模式；研究指标使用原生基模S11/S21，同时核查原生多模/端口证据。
- 最新单例7次自适应阶段请求+1次最终扫频，共8次Analyze。一个Analyze可以含多轮自适应，不等于一个几何。

这些是最新单例的记录，不意味着所有历史数据都使用相同网格或核数。早期16核与后期14核、旧高网格结果均保留原标签。

## 完成hook的正确链路

真正求解终态 → 原生数据导出和检查 → 保存不可变事件 → 去重投递到授权聊天 → 接收方独立核验 → 实际看图ACK → 明确允许时才接续下一项。

通知成功只表示消息被接受，不表示设计通过或AI已处理。失败事件要区分求解/导出/投递/接续故障。worker/observer身份检查应结合PID、创建时间及完整命令，而不是PID存在就通过。

用户要求的心跳场景是：**完成消息发出后，约5分钟仍没有新仿真时，再检查AI是否仍在处理或已中断**；正常仿真期间不应周期刷消息。处理中就等待；中断才在持久化去重和有限预算内提醒；投递不确定不盲目重发；用户暂停优先。

## 随附工具的版本边界

[通用hook 1.1.0](../tools/completion-hook-1.1.0/README.md) 是当时打包的可移植源码，默认守护参数与后期各批次专用的5分钟状态机不完全相同。**不能声称1.1.0已包含所有后续修复**。专用迭代代码保存在archive中，源码采用`.py.txt`，仅供审计。

新电脑安装时必须重新授权目标聊天、检查支持的消息工具；不复制本机管道、ID和活动队列。当前仓库不携带运行中的hook配置。通用工具在第二台电脑和不同客户端上的可靠性仍需实测；不能承诺直接唤醒网页ChatGPT/Grok。

## 工程复用与恢复

[hfss/INV01_A14.aedt](../hfss/INV01_A14.aedt)是最后单例的真实工程，原字节保留，不附结果缓存。新机需要自己的Ansys许可、材料和求解资源；打开工程/重新求解需要独立操作授权。克隆后不会自动运行。

历史中出现过AEDT退出、工程加载卡住、扫频提交超时、导出连接超时和外部任务资源冲突，未证明一个共同根因。不要将技术失败当设计失败；不要清锁、无限重启、无限补算或覆盖原失败记录。任何恢复应在独立尝试目录内保留原参数、预算与证据，且尊重用户暂停。
