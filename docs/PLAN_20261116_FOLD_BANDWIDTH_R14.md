## 1. 审核结论

- **停止正确，没有浪费。** 新增 0 个几何、0 次 Analyze，`charge()` 没有执行。原 R4 缓存 597 个文件字节一致；副本的几何、材料、端口、Rad1、27 轮历史以及原生 ValidateDesign 都通过。
- **原因清楚。** `observer_r13.py` 由 `solve_block.py` 用 `subprocess.Popen([sys.executable, …])` 启动，是一个全新的 Python 进程。它第 7 行 `from common_r6 import …`，但新进程没有 R6 目录的路径。worker 自己的 `sys.path` 不会传给子进程。Codex 已经在全新解释器里复现了这个错误。
- **这是测试的盲区，不是规则的问题。** 55 项回归都在同一个解释器里导入模块，测不到“子进程从零启动”这条路径。所以修复的重点在于让每个子进程入口都在真实条件下被测到。
- **R13 的判断不变。** 第 2.1 节的 ΔS 平台、只扫频的理由、三档统计稳健标注、C1R 判定、Q25–Q26 都没有新数据，原样有效。

## 2. R6：修复与测试

1. **修路径。** 在 `observer_r13.py` 的 R6 副本里，导入 `common_r6`、`roles_r6` 之前，先把所需目录加进 `sys.path`，做法与 `common_stage2.py` 的前几行相同。不依赖父进程的环境变量或工作目录。只改导入方式，不改观察逻辑。
2. **列出全部子进程入口。** 列出本轮所有用 `Popen` 或 `subprocess` 启动的 `.py` 脚本，至少包括 `worker_stage2.py` 和观察器，写进冻结文件。
3. **真实入口导入测试。** 对每个入口，都用全新的 `python -I` 子进程，以真实启动时的工作目录（以及一个无关的临时目录）只做导入，不运行 main，不连 AEDT。返回码必须为 0。
4. **观察器空跑测试。** 用一个假的工作目录和假的 `owner.json`（指向测试进程本身），按 `solve_block.py` 的方式实际启动观察器子进程，然后：
   - 等它写出 ready；
   - 创建 stop 文件；
   - 确认它在 20 秒内以返回码 0 退出，并且输出文件格式正确。

   测试中不能出现 `ansysedt.exe` 或 `hf3d.exe`，也不连 AEDT。
5. **回归。** R5 的 55 项、默认 11 项和归档校验照跑。第 3、4 条的新测试要先在 R5 原代码上失败（复现本次故障），再在 R6 上通过，两次结果都写进冻结。

## 3. 执行者可以自行修复的范围

用户每次转交都要花时间，所以本轮允许执行者在下面这个窄范围内自己修好再继续，不必停下来等审核。

**同时满足下列条件才可以自行修复：**

- 故障发生在 `charge()` 之前：没有计费，没有向 HFSS 提交求解；
- 故障属于工具打包类：导入路径、缺文件、入口参数、拼写；
- 修复不改变判据、几何、材料、网格或扫频设置、预算、冻结的数值和预测；
- 修复前先写一个能在全新解释器里复现该故障的测试，修复后这个测试通过，其余回归全部通过；
- 修复以 R6 的补丁版本冻结并推送之后，才重试；
- 本轮总共最多自行修复 2 次。

**其余任何情况都照 R13 第 3.5 节立即停。** 比如已经计费、HFSS 进程异常、验证有 error、哈希不符，或者第 3 次出现工具故障。

报告里要逐条列出自行修复的内容：故障、复现测试、补丁提交、重试结果。
