## 3. 我的程序错误、修复与成本

问题不在HFSS求解器。R2定义：
`Lc = Ls1 + 2Ls2 + 2Ls3 − 4Ws`；
代入`Ls2=2Ws+g, Ls3=a+Ws`后应是
`Lc = Ls1 + 2a + 2g + 2Ws`。

原新调参器反解Ls1时用了`2a+2g+4Ws`，多扣2Ws。受影响的唯一已派发参数点是N04/a=.6的T2，Ws=.365 mm时槽长短了.730 mm：
错误12.966 mm，正确13.696 mm。

发现后：
1. 不杀正在求解的HFSS，让当前原生16轮自适应正常返回，再阻止下一次Analyze；保留缓存、输入、原始16轮和失败记录。
2. 此次仍记1个几何/1次API；它不是完整求解、数值通过或物理设计失败。
3. 原执行目录及STOP不修改。新建独立修正版，继承原5几何/47次API的真实成本，剩余上限37几何。
4. 修正版直接用R2的dimensions()反解中心线，增加长度恒等式断言、全部R3几何恒等式、已知.730 mm案例及跨版本预算覆盖测试。
5. 使用N04/a=.6原第3次、也是最后一次几何额度验证修正；校准依据为未受影响的T1，不使用错误T2作物理拟合。修正版实际求解完成，中心线断言与原生槽盒通过。

## 4. 为什么在这里停止

N04共有5个父设计。直槽和a=.6都已在各自原3次额度内结项但未调准，因此：
`最多可调准数 = 5 − 2 = 3 < 4`。

即使把剩余3个N04、5个N14以及全部条件对照继续跑完，按现有单设计上限也无法达到进入阶段4的数量条件。故依R4第5节停止，避免继续消耗；不是以“难、慢”或“全部物理不可达”为理由停止。阶段3仍有36个未用几何额度，但不能自动把它们转换成已用满父设计的第4次。
